# Sprint 03: Otomasi Cutover Vanity Domain, Background Data Backfill, Paritas Object Storage & Operational Runbook

## 1. Tujuan & Outcome Sprint

### Tujuan Sprint
Memperkuat kapabilitas operasional dan kehandalan pasca-migrasi `laravel-cloud-migrator` melalui implementasi perintah cutover vanity domain yang tahan banting (`vanity:transfer`) berbasis temuan spike API Laravel Cloud, pipeline pengisian data historis masif non-blocking (`db:backfill`) dengan adaptif batching dan checkpointing lokal, audit paritas object storage komprehensif (`storage:verify`), deteksi drift lingkungan otomatis (`org:audit`), serta penyusunan runbook operasional dan disaster recovery lengkap.

### Outcome Sprint
- Perintah CLI `./cloud-migrator vanity:transfer` (`App\Commands\VanityTransferCommand`) dan service pendukung `App\Services\VanityTransferService` beroperasi penuh dengan dukungan swap vanity domain, dynamic retry backoff untuk reservation cooldown lock, deteksi collision, safety confirmation, dan garansi rollback instan.
- Pipeline `db:backfill` (`App\Commands\BackfillDbCommand`) tersedia untuk replikasi data historis bertahap tanpa membebani IOPS database produksi dengan checkpointing terkelola (`.backfill-state.json`).
- Command audit `storage:verify` (`App\Commands\VerifyStorageCommand`) memvalidasi integritas multi-bucket source vs target (size parity, checksum MD5/ETag) tanpa transfer fisik objek.
- Command agregat `org:audit` (`App\Commands\AuditOrgCommand`) dan GitHub Actions workflow template mendeteksi drift konfigurasi, health check 17 environment, dan anomali database secara otomatis.
- Dokumentasi operasional terpadu `docs/runbooks/operations-and-dr.md` menyajikan prosedur standar cutover, penanganan insiden, dan mitigasi disaster recovery.
- Automated test suite Pest (134+ tests, 500+ assertions) dan linter Laravel Pint 100% clean.

## 3. Rujukan Teknis & Spike API Laravel Cloud

Pengembangan perintah `vanity:transfer` berpijak pada temuan empiris yang didokumentasikan pada:
- **Dokumen Spike**: [docs/spikes/vanity-transfer.md](../spikes/vanity-transfer.md)
- **Temuan Kunci Spike**:
  1. Penetapan vanity domain dilakukan via dedicated endpoint `PUT /api/environments/{environment_id}/vanity-domain` dengan payload JSON `{"name": "<subdomain>"}`.
  2. Saat domain sedang dipakai, API merespons `HTTP 422 Unprocessable Entity: This Laravel Cloud domain is already taken.`.
  3. Pelepasan via rename memberlakukan *reservation lock / cooldown window* (>30 detik), sehingga klaim oleh target org membutuhkan dynamic retry backoff.
  4. Pemilik asli memiliki hak rollback instan (<2 detik) untuk merebut kembali nama vanity domain jika klaim target gagal.
  5. Pelepasan via penghapusan environment/app (`DELETE /environments/{id}` atau `--delete-source`) melepaskan vanity domain secara global seketika (~2,06 detik) tanpa masa cooldown.

## 5. Log Eksekusi & Evaluasi DoD Task 1

### Detail Pekerjaan Task 1
1. **Pembaruan Core API Client (`App\Services\CloudApiClient`)**:
   - Menambahkan method `put(string $path, array $data = []): array` untuk mendukung pemanggilan HTTP PUT standar Laravel Cloud API.
   - Memperbarui `throwApiError` agar menyertakan kode status HTTP asli (`$e->getResponse()->getStatusCode()`) pada `RuntimeException`, memungkinkan penanganan status 422 secara terprogram.
   - Menambahkan unit test di `tests/Unit/CloudApiClientTest.php` untuk verifikasi sukses dan kegagalan status 422 pada `put()`.

2. **DTO Hasil Transfer (`App\Data\VanityTransferResult`)**:
   - Dibuat kelas `readonly class VanityTransferResult` yang menyimpan metadata eksekusi: status (`transferred`, `already_set`, `failed`, `rolled_back`), vanity subdomain, nama app/env asal & tujuan, jumlah percobaan retry backoff, durasi eksekusi, log historis, dan data respons environment target.

3. **Service Vanity Domain Transfer (`App\Services\VanityTransferService`)**:
   - Menangani siklus transfer secara modular:
     - `findApp()` dan `findEnvironment()`: Pencarian resource berdasarkan nama, slug, atau ID.
     - `normalizeVanity()`: Normalisasi input subdomain (menghapus protokol `https://` dan suffix `.laravel.cloud`).
     - `isReservationLocked()`: Deteksi presisi terhadap kode status HTTP 422 dan pesan reservasi/cooldown.
     - **Mekanisme Release Ganda**:
       - *Safe Archive Mode* (`--delete-source=false`): Me-rename vanity sumber ke nama arsip acak (`{vanity}-archived-{random}`) sebelum klaim target.
       - *Instant Deletion Mode* (`--delete-source=true`): Menghapus environment sumber (`DELETE /environments/{id}`) untuk pelepasan instan tanpa cooldown lock.
     - **Dynamic Polling Retry Backoff**: Melakukan perulangan klaim `PUT /environments/{id}/vanity-domain` dengan backoff bertahap (delay awal 1.000 ms, multiplier 1.5x, ceiling 5.000 ms) hingga `$maxAttempts` tercapai.
     - **Safety Rollback Automatis**: Jika klaim target gagal/timeout dan sumber belum dihapus, service secara otomatis memanggil `PUT /environments/{source_env}/vanity-domain` untuk mengembalikan nama vanity asli ke sumber tanpa intervensi manual.
     - Mendukung injeksi custom sleeper function untuk pengujian deterministik berkecepatan tinggi di unit tests.

4. **Command CLI (`App\Commands\VanityTransferCommand`)**:
   - Command `./cloud-migrator vanity:transfer` menggantikan helper lama dengan antarmuka yang lebih kaya dan aman.
   - Pilihan konfigurasi fleksibel: `--source-app`, `--source-env`, `--target-app`, `--target-env`, `--vanity`, `--delete-source`, `--max-retries`, `--retry-delay`, dan `--yes`.
   - Menampilkan visualisasi tabel rencana (*Plan Table*) sebelum eksekusi.
   - Deteksi dini tabrakan (*collision alert*) dan konfirmasi protektif interaktif.
   - Pelaporan status hasil transfer yang informatif dengan durasi dan jumlah percobaan.

5. **Automated Testing Suite (Pest)**:
   - `tests/Unit/VanityTransferServiceTest.php` (12 unit tests):
     - Normalisasi domain, deteksi error lock 422, pencarian app & environment.
     - Transfer sukses percobaan ke-1, auto-detect vanity sumber, early success bila target telah memiliki vanity.
     - Simulasi dynamic retry backoff dengan 422 lock yang sukses pada percobaan ke-3.
     - Transfer dengan pelepasan deletion `--delete-source`.
     - Rollback otomatis ke sumber saat percobaan habis.
