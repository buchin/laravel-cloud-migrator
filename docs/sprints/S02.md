# Sprint 02: Peningkatan Reliabilitas Tooling, Migrasi Deklaratif, Sinkronisasi Storage & Source Teardown

## 1. Tujuan & Outcome Sprint

### Tujuan Sprint
Memperkuat kapabilitas, reliabilitas, dan otomasi `laravel-cloud-migrator` melalui standardisasi pipeline database anti-deadlock & dynamic auto-chunking, manifest migrasi deklaratif (`migration-plan.json`), fitur sinkronisasi object storage (`storage:sync`), serta eksekusi aman dekomisioning/teardown organisasi sumber (*source org*) pasca migrasi penuh yang divalidasi dengan pre-flight audit komprehensif.

### Outcome Sprint
- Feasibility spike API Laravel Cloud untuk mekanisme Swap & Claim vanity domain berhasil dieksekusi dan didokumentasikan di `docs/spikes/vanity-transfer.md`.
- Pipeline migrasi database di-upgrade dengan flag anti-deadlock permanen (`--skip-add-locks`, `--quick`, `--compress`, `foreign_key_checks=0`) dan dynamic auto-chunking untuk tabel berukuran >1 GB atau >100.000 baris.
- Format manifest deklaratif `migration-plan.json` diimplementasikan untuk mengatur kebijakan migrasi per-tabel (`schema_only`, `chunked`, `ignore`, `transient`) dan resolver dependensi cross-app env variable.
- Perintah `storage:sync` (`SyncStorageCommand`) tersedia untuk sinkronisasi multi-bucket object storage/S3 dengan validasi checksum MD5/ETag dan streaming paralel.
- Command helper `org:teardown` dengan proteksi *double confirmation* berhasil mengeksekusi pembersihan resource di source org secara aman setelah seluruh pre-flight audit di target org berstatus 100% sehat.
- Test suite Pest (35+ tests) dan linter Laravel Pint berjalan clean tanpa kegagalan.

## 5. Aturan Teknis & Safety Protocol

1. **Proteksi Mutlak Resource Produksi**:
   - Selama pelaksanaan task spike maupun pengembangan tooling, dilarang keras memodifikasi atau menghapus 6 aplikasi aktif di target org (`termapi`, `dracin-api`, `dojo`, `stats`, `nerd`, `dracin`).
   - Setiap pengujian wajib menggunakan sandbox terisolasi dan dibersihkan segera setelah pengujian selesai.
2. **Standardisasi Anti-Deadlock**:
   - Operasi `mysqldump` wajib menyertakan: `--single-transaction`, `--skip-add-locks`, `--quick`, `--compress`.
   - Restore script wajib diawali dengan:
     ```sql
     SET @OLD_FOREIGN_KEY_CHECKS=@@FOREIGN_KEY_CHECKS, FOREIGN_KEY_CHECKS=0;
     SET @OLD_UNIQUE_CHECKS=@@UNIQUE_CHECKS, UNIQUE_CHECKS=0;
     ```
     dan diakhiri dengan pemulihan nilai semula.
3. **Double Confirmation pada Operasi Destruktif**:
   - Perintah `org:teardown` tidak boleh dapat dijalankan secara tidak sengaja. Wajib meminta input konfirmasi teks eksplisit (misal: mengetikkan string acak atau nama slug org yang akan dihapus).
4. **Data Verification Pre-Teardown**:
   - Teardown source org hanya boleh dimulai jika `./cloud-migrator db:verify` dan `./cloud-migrator org:status` menyatakan keselarasan 100%.

## 7. Risiko, Mitigasi, dan Batasan (Out-of-Scope)

### Risiko & Mitigasi
- **Risiko: Reservation Lock Vanity Domain Menimbulkan Downtime**:
  - *Mitigasi*: Feasibility spike membuktikan bahwa metode `DELETE /applications/{id}` langsung melepaskan vanity domain secara global (~2.061 ms) tanpa terkena reservation lock 30+ detik seperti pada metode rename.
- **Risiko: Deadlock saat Dump Database Skema Besar**:
  - *Mitigasi*: Implementasi flag anti-deadlock permanen dan dynamic chunking berbasis primary key / limit-offset.
- **Risiko: Penghapusan Tidak Sengaja pada Target Org**:
  - *Mitigasi*: Whitelist token ketat, validasi ID aplikasi, dan double confirmation guard pada `org:teardown`.

### Batasan (Out-of-Scope)
- Modifikasi arsitektur internal aplikasi klien (`buchin/*` repositories).
- Penambahan cluster database baru di luar yang telah termigrasi di Sprint 01.
