# Sprint 01: Migrasi Komprehensif Infrastruktur Laravel Cloud

## 1. Tujuan & Outcome Sprint

### Tujuan Sprint
Melakukan migrasi seluruh ekosistem aplikasi dari organisasi sumber (*source org*) ke organisasi target (*target org*) di Laravel Cloud secara terstruktur, aman, dan terkontrol tanpa kehilangan integritas data maupun gangguan layanan permanen.

### Outcome Sprint
- 6 aplikasi aktif di target org dengan total 17 environment yang terkonfigurasi identik dengan source org.
- 2 target database cluster (`dojo` dan `dracin_api`) serta 1 cache Valkey (`dojo`) berhasil diprovisioning dan terhubung.
- Database data termigrasi sesuai kebijakan integritas data: data inti termigrasi penuh, tabel historis/cache berat diskip sesuai kesepakatan (0 mismatch pada tabel aktif via `db:verify`).
- 9 custom domain terhubung ke target org dengan SSL aktif dan status respons HTTP 200 OK.
- Manual cutover gate untuk 2 vanity domain penting (`termapi.laravel.cloud` dan `dracin-api.laravel.cloud`) sukses dieksekusi bersama PO.
- Laporan verifikasi komprehensif (`org:status`, `org:health`, `db:verify`) membuktikan status sistem 100% sehat dan sinkron.

## 5. Aturan Khusus Data Skipping & Migrasi

Berdasarkan kesepakatan Sprint Planning bersama PO, migrasi database dilakukan secara selektif untuk mengoptimalkan waktu eksekusi dan efisiensi penyimpanan:

1. **`nerd.links`**:
   - Struktur tabel (schema/DDL) dimigrasikan.
   - Data baris **di-skip** (`--ignore-table=nerd.links`).
2. **`dojo.nerd_urls`**:
   - Struktur tabel (schema/DDL) dimigrasikan.
   - Data baris **di-skip** (`--ignore-table=dojo.nerd_urls`).
3. **`dracin_api.episodes`**:
   - Struktur tabel (schema/DDL) dimigrasikan.
   - Data baris **di-skip** (`--ignore-table=main.episodes`).
4. **`dracin_api.dramas`**:
   - Data penuh (~5.0 GB) **wajib termigrasi** secara utuh dan terverifikasi 0 mismatch baris.
5. **Tabel Transient (otomatis diakomodasi oleh `db:verify`)**:
   - Tabel `jobs`, `cache`, `cache_locks`, `sessions`, `job_batches` diperlakukan sebagai transient data.

## 6. Manual Vanity Cutover Gate (Task 5)

Domain bawaan `*.laravel.cloud` terikat pada organisasi Laravel Cloud dan tidak dapat dipindahkan otomatis antar-organisasi via API. Oleh karena itu, ditetapkan gate khusus:

1. **Gate Target**:
   - `termapi.laravel.cloud`
   - `dracin-api.laravel.cloud`
2. **Prosedur Cutover**:
   - Seluruh target environment dan database sudah 100% siap dan terverifikasi.
   - Koordinasi dengan PO untuk melepaskan slug vanity di source app dashboard (atau renaming slug sementara di source).
   - Segera klaim slug yang dilepas ke aplikasi target di target org (`vanity:transfer` atau update slug).
   - Jalankan smoke probing HTTP 200 secara berkala hingga DNS/routing stabil.

## 7. Risiko, Mitigasi, dan Batasan (Out-of-Scope)

### Risiko & Mitigasi
- **Ukuran Data dracin_api.dramas (~5 GB)**:
  - *Mitigasi*: Per-table data streaming dump via `mysqldump` lokal dengan optimasi buffering dan unbuffered pipeline; tabel `episodes` diskip.
- **Resource Collision / Duplikasi Cluster**:
  - *Mitigasi*: Penggunaan `useSharedRegistries` pada `MigrationService` memastikan `stats`, `nerd`, dan `dojo` menggunakan target DB cluster dan cache yang sudah dibuat pada Task 1.
- **Propagasi Vanity Domain**:
  - *Mitigasi*: Penggunaan retry loop otomatis 5 menit dan fallback manual sesuai dokumentasi Laravel Cloud.

### Batasan (Out-of-Scope)
- Migrasi data object storage (S3 bucket contents).
- Decommission / penghapusan aplikasi di source org (hanya dilakukan pasca Sprint Review dan persetujuan PO).
- Penambahan fitur aplikasi baru di luar operasional migrasi.
